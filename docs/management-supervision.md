# Phase 3B 管理同期ジョブの復旧・監視・通知

対象: dev/local-isolation。実装・試験はローカル代替のみ。実Square、Resend、Cloudflareへの接続、実SQL、デプロイ、コミット・プッシュは行わない。

## 復旧の順序

1. 検証済み環境・管理者認証・入力・固定操作ID・既存のSKU保留を確認する。
2. D1保存直後の停止に備えてDO Alarmを先に予約する（失敗も安全な固定文で記録する）。
3. ジョブ・対象Variationのロック・監査をD1.batchで同時保存する。
4. 保存後にもう一度Alarm予約を確認する。確認できなければqueuedのままとし、Squareへ送信しない。
5. 実行・再実行の直前にも予約を確認する。既存の固定キー・保存済み本文・対応表を使い、結果が保存済みならD1反映だけ進める。
6. DO最初の処理時の起動スキャン、既存Alarm、独立したscheduled入口から同じ管理ジョブを監視する。既存購入と同じDOの直列キューを通し、1回の監視で実行する管理ジョブは1件。

Alarmだけに依存しない。Alarm APIが故障したままなら外部同期は開始せず、Cronから未完了を検出し、長時間未完了の通知と対象Variation保留を維持する。通常購入を店舗全体で停止する機構は追加しない。注文側Alarmが失敗してもfinallyで管理監視を試行する。監視は公開Catalogの読込に依存しない。D1自体が停止している間は読取・復旧・通知保存を保証できず、次回の独立監視で再検出する。

リモート用管理設定テンプレートには5分ごとのCronだけを追加する。本番設定には追加しない。ローカル管理CLIは60秒ごとの独立タイマーでDO監視を呼び、閉じると解除する。DO Alarmは最大60秒先に監視を予約する。画面を開くことは復旧の条件ではない。ただしローカルではCLIプロセス自体の稼働が必要で、停止中は処理できず再起動後に復旧する。

## 判定と通知

- queued/running/retryを検出し、dueのジョブを1件ずつ復旧する。
- 結果未確定で作成から1時間超、または8回到達はreview。保留を解除せず、新しいキーで再送しない。
- Square結果がD1へ保存済みなら、期限経過後も既存結果からDB反映を試行できる。
- review、または作成から15分以上未完了のジョブを通知対象にする。すぐ復旧したジョブの未送信通知は取消。
- 新規Item ID不明、在庫の成功証跡なし、価格・バージョン不一致の照合は既存ルールを維持する。数量を初期化したり、新商品として再作成したりしない。

追加テーブルは0002_management_supervision.sqlのmg_job_notificationsとmg_management_monitorだけ。既存注文・ジョブ・対応表を削除/初期化せず、追加マイグレーションとして適用する。ローカルCLIは既存状態へCREATE IF NOT EXISTSで追加する。

通知対象を永続化し、ジョブIDを主キーに1通知を保持する。payloadは検出時の固定値（ジョブID、操作種別、商品/Variationの内部ID、review/stalled）で、送信時に内容を書き換えない。キーはmanagement-sync-<jobId>で注文通知と区別する。送信前に試行日時・回数を保存し、応答消失や通知結果のDB保存失敗は同じキーと本文で再確認する。最大8回・初回送信試行から1時間で自動送信を止め、expiredを表示する。送信済み履歴はジョブ復旧後も保持し、新しいキーでの自動再送はしない。

既存sendResendEmailを再利用し、既存設定の管理者宛1件だけへ送る。Sandbox検証では既存の送信元・宛先制限とD1識別マーカー検証が先行する。キーやSecretを追加せず、ローカルは代替メール。Secret/URL/顧客情報/画像データ/生のエラーは新しい通知・ログへ含めない。通知設定不足はblockedとして表示し、実送信試行枠は消費しない。sentはプロバイダーの送信受付を確認した意味で、受信箱への到達保証ではない。

プロバイダー側の冪等性保証は実Resendで未検証。設定変更（宛先・送信元など）は未確定通知の再試行中に行わず、結果を照合する。expiredの通知を手動で新キー再送する操作画面は追加していない。管理者は履歴を確認して判断する。

## 管理画面

既存の公開状態を維持し、その隣にSquareの「同期待ち/同期中/再試行待ち/要確認/前回同期完了/未連携」と未反映下書きの有無を別表示する。「前回同期完了」は最新の外部変更まで保証する表示ではない。ジョブ一覧に最終監視時刻、Alarm失敗、通知設定待ち/送信受付済み/通知結果要確認を追加する。CSS、商品カード、写真読込、CSRF、Origin許可範囲は変更しない。

- prepare-managementから検証用Git対象外設定を再生成し、5分Cron、専用D1/DO/R2、Sandbox接続・既存通知制限をレビューする。以前の生成設定は自動で書き換えていない。

- 在庫書込みdisabledは維持する。実Square操作、在庫変更、購入・メールの試験は別途承認の対象。

## 保存承認時の追加最終確認
