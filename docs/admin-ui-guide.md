# 八草屋本店 ショップ運営画面

2026-10-21 / dev/local-isolation。画面の変更とローカル試験のみ。コミット・プッシュ・公開・デプロイは別途承認後。

## 起動とAndroidでの確認

リポジトリルートで実行する。Wrangler、Square、Cloudflareの認証は不要。

```sh
npm ci --prefix dev --no-audit --no-fund
npm --prefix dev run management -- --seed --seed-orders
```

Codespacesでは8000番のPort Visibilityを **Private** に保ち、Open in Browserから `/admin/` を開く。ローカル専用の `local-development-only` でログイン。転送URLや実際のトークンをGitへ保存しない。Codespaces固有のホスト検査・外向き通信拒否は従来どおり。最新版のコードは未コミットのため、別のCodespacesへは自動反映されない。

既存の `dev/.state/management` は保持する。起動時に既存のローカル商品や在庫は初期化しない。架空注文も重複追加せず、発送済みへ変更した状態を保持する。停止はCtrl+C。

## 画面の使い方

- **ホーム**：発送待ち数、登録商品数、3個以下の在庫、最近の注文を確認。未確認・販売保留は在庫確認リストへ表示。取得失敗を0件扱いにしない。注文APIの制限に合わせ、各状態の直近200件までを集計し、上限に達した発送待ち数には「+」を付ける。
- **注文**：発送待ち／発送済みを切り替え、カードを押して詳細を開く。発送方法・追跡番号を入力し「発送を確定する」で内容を確認する。ローカルでは実メールを送信しない。発送中は二重操作とダイアログ閉じを防ぐ。
- **商品**：商品名・バリエーション名で検索し、公開状態で絞り込む。写真・価格・状態をカードで確認。「商品登録」または「編集」でフォームを開く。下書き保存は公開内容を変えない。保存済みの内容を確認して公開する。販売停止、アーカイブ、既存Sandbox ID関連付けは「販売状態・連携設定」内。同期の再試行・結果照合・取込は「同期・変更履歴」内。
- **写真**：最大10枚。プレビュー下の↑／↓で順序を変更し、先頭がメイン写真になる。「外す」は下書きからの取り外しで、保存前には公開へ反映されない。JPEG/PNG/WebP、端末で変換できるHEICを扱い、従来の縮小・サイズ・形式・メタデータ検査を使用する。
- **在庫**：「入庫」は追加数、「棚卸し」は数えた最終数、「増減調整」は符号付きの増減数。理由を入力すると変更前後の数量を表示し、確認後に送信する。最新の在庫と表示時点をサーバーが照合する。販売保留・未対応の行では操作を無効にする。

読み込み・成功・失敗を画面内のメッセージと通知で表示。未保存の編集にはバッジと破棄確認を設ける。通信失敗時の再送は、画面を閉じずに同じ内容で行う。成功応答を受けるまで元の操作IDを保持する。競合・保留を新しいキーで無理に上書きしない。

## デザインと操作支援

生成り・白・チャコール・植物系グリーン、既存の商品写真を使用。640px以下は4項目の下部ナビとsafe-area余白、広い画面はサイドナビ。入力文字は16px、主要ボタンは44px以上。見出しフォーカス、現在位置、入力ラベル、ライブメッセージ、モーダルのキーボード操作に対応。写真の並び替えにはドラッグ不要のボタンを使う。外部アイコン・フォント・UIライブラリは追加しない。

管理APIの未設定時に本番URLへフォールバックしない。検証用Assets生成時は、新しい管理スクリプト2本にも既存のSandbox・同一オリジン検査を付ける。API、購入DO、台帳、同期ジョブ、在庫保留、マイグレーションは今回変更していない。

## テスト

```sh
npm --prefix dev test
npm --prefix dev run test:ui
```

`test:ui`はPlaywright Core 1.57.0とChromiumを使用する。ブラウザーがない場合は `npm exec --prefix dev -- playwright-core install chromium` でテスト用ブラウザーを導入し、必要なOSライブラリを用意する。既定では `/usr/bin/chromium` があれば使用し、なければPlaywrightが導入したChromiumを使用する。別の場所なら `YASOYA_CHROMIUM_PATH` で実行ファイルを指定する。これはローカル試験用で、Cloudflare操作はしない。通常の管理サーバー起動にChromiumは不要。

8000番を使うため管理サーバーを停止してから実行する。既存プロセスを勝手に終了しない。ブラウザーテストはメモリー上の専用D1/DO/R2・Square/メール代替を生成し、既存の `dev/.state` を触らない。ページの同一オリジン以外のリクエストは遮断し、外部アクセス試行・未処理JSエラー・決済呼び出しが0件であることも検査する。

任意の `YASOYA_UI_ARTIFACTS` ディレクトリにローカル画面のPNGを出力できる。Git管理下へ実データの画面を保存しない。今回の試験は架空データだけ。

ブラウザー12ケース：ログイン・ホーム集計・下部ナビ、写真付き検索/状態フィルター、未保存破棄確認/下書きと公開の分離、商品新規登録/写真2枚/並び替え/バリエーション、入庫/棚卸し/確認キャンセル、更新成功後の通信切断と同一キー再試行、外部在庫競合、保留中の操作禁止、発送確認/二重タップ/追跡番号/集計更新、取得失敗とローディング、320/360/390/412/768/1280pxの全画面・編集ダイアログ、外部アクセス/決済/JSエラーなし。

実行結果：`npm --prefix dev test` は100件成功（既存98件＋管理画面の接続先チェック2件）、失敗0・スキップ0、約97秒。`npm --prefix dev run test:ui` は12件成功、失敗0・スキップ0、約21秒。6種類の幅で横はみ出しがなく、長い編集フォームを最下部までスクロールしても閉じる・保存ボタンが表示されることを確認。390pxと1280pxの画面をPNGでも目視確認した。既存の安全性テストはDOMの代替要素にイベント登録メソッドを追加しただけで、接続先・通信拒否の検証は維持。JavaScript構文チェックと `git diff --check` も成功。

## 残る制約

実Android・実Codespaces転送・実Square Sandbox・Cloudflare Access・実メール送信は今回検証していない。Chromiumのスマホ相当幅・タッチ設定で確認した結果であり、Androidのキーボード、HEIC変換、スクリーンリーダー、OSの文字拡大は実機で確認する。ページ再読込をまたぐ管理操作IDの保存方式は今回拡張していない。通信断後は編集を閉じず同じ内容で再試行し、再読込した場合は同期履歴と現在値を先に確認する。Square外部販売経路との在庫競合など、既存の安全性上の制約は `management-system.md` を引き継ぐ。
