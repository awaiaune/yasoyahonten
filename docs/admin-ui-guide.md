## 画面の使い方

- **ホーム**：発送待ち数、登録商品数、3個以下の在庫、最近の注文を確認。未確認・販売保留は在庫確認リストへ表示。取得失敗を0件扱いにしない。注文APIの制限に合わせ、各状態の直近200件までを集計し、上限に達した発送待ち数には「+」を付ける。
- **注文**：発送待ち／発送済みを切り替え、カードを押して詳細を開く。発送方法・追跡番号を入力し「発送を確定する」で内容を確認する。ローカルでは実メールを送信しない。発送中は二重操作とダイアログ閉じを防ぐ。
- **商品**：商品名・バリエーション名で検索し、公開状態で絞り込む。スマホでは2列の正方形フォトカードで写真・名前・内容量・価格・状態を確認し、カード全体をタップして編集する。長い名前は3行まで表示し、全文は編集フォームで確認できる。下書き保存は公開内容を変えない。保存済みの内容を確認して公開する。販売停止、アーカイブ、既存Sandbox ID関連付けは「販売状態・連携設定」内。同期の再試行・結果照合・取込は「同期・変更履歴」内。
- **写真**：編集画面の先頭に大きなギャラリーを表示。最大10枚を左右スワイプ・ドットボタン・左右矢印/Home/Endキーで閲覧する。「写真n/m」で位置を確認できる。閲覧だけでは順序や未保存状態は変わらない。「写真の順序・メイン画像を編集」を開き、↑／↓で並び替え、または「メインにする」でその写真を先頭へ移す。ドラッグやスワイプでは並び替わらない。「外す」は確認後に下書きから取り外し、保存前には公開へ反映されない。JPEG/PNG/WebP、端末で変換できるHEICを扱い、従来の縮小・サイズ・形式・メタデータ検査を使用する。
- **在庫**：「入庫」は追加数、「棚卸し」は数えた最終数、「増減調整」は符号付きの増減数。理由を入力すると変更前後の数量を表示し、確認後に送信する。最新の在庫と表示時点をサーバーが照合する。販売保留・未対応の行では操作を無効にする。

読み込み・成功・失敗を画面内のメッセージと通知で表示。未保存の編集にはバッジと破棄確認を設ける。通信失敗時の再送は、画面を閉じずに同じ内容で行う。成功応答を受けるまで元の操作IDを保持する。競合・保留を新しいキーで無理に上書きしない。

## デザインと操作支援

生成り・白・チャコール・植物系グリーン、既存の商品写真を使用。640px以下は4項目の下部ナビとsafe-area余白、広い画面はサイドナビ。入力文字は16px、主要ボタンは44px以上。見出しフォーカス、現在位置、入力ラベル、ライブメッセージ、モーダルのキーボード操作に対応。写真の並び替えにはドラッグ不要のボタンを使う。外部アイコン・フォント・UIライブラリは追加しない。

管理APIの未設定時に本番URLへフォールバックしない。検証用Assets生成時は、新しい管理スクリプト2本にも既存のSandbox・同一オリジン検査を付ける。API、購入DO、台帳、同期ジョブ、在庫保留、マイグレーションは今回変更していない。

## Phase 2の共通UI部品

`js/admin-ui.js` は外部依存のない表示専用モジュール。ヘッダーのブランド適用、CSSカラートークン、商品カード・写真サムネイル・ギャラリー・状態バッジ・空状態・読み込み表示を提供する。既存の `YasoyaAdmin` は認証付きAPI・冪等性キー・通知・メッセージを引き続き担当し、重要操作の確認は従来のconfirmを使う。フレームワーク移行やバックエンド/DB変更は行わない。

任意の `window.YASOYA_ADMIN_BRAND` から受け取るのは `name`、`wordmark`、`colors` の4トークン（paper/ink/green/soft）だけ。色は6桁の16進カラーのみ。文字列はtextContentで適用し、URL・HTML・認証・接続先・テナントIDなどの追加フィールドは無視する。既定は八草屋本店で、葉アイコンやロゴ画像は置かず2段の文字表記とする。将来ロゴを使う場合も表示用領域に限定する。今回は他ブランドのアプリ、データストア、認証、Square接続を作成・共有しない。

ギャラリーは画像IDと画像ロード関数を受け取るだけで、APIや保存仕様を知らない。メイン指定は既存の `draft.images` 配列の先頭変更で実現し、新しいDB項目やAPIは不要。写真ロードには従来の認証付き画像APIとBlob URLキャッシュを使う。保存・公開・再送の処理内容は維持する。

## テスト

```sh
npm --prefix dev test
npm --prefix dev run test:ui
```

`test:ui`はPlaywright Core 1.57.0とChromiumを使用する。ブラウザーがない場合は `npm exec --prefix dev -- playwright-core install chromium` でテスト用ブラウザーを導入し、必要なOSライブラリを用意する。既定では `/usr/bin/chromium` があれば使用し、なければPlaywrightが導入したChromiumを使用する。別の場所なら `YASOYA_CHROMIUM_PATH` で実行ファイルを指定する。これはローカル試験用で、Cloudflare操作はしない。通常の管理サーバー起動にChromiumは不要。

8000番を使うため管理サーバーを停止してから実行する。既存プロセスを勝手に終了しない。ブラウザーテストはメモリー上の専用D1/DO/R2・Square/メール代替を生成し、既存の `dev/.state` を触らない。ページの同一オリジン以外のリクエストは遮断し、外部アクセス試行・未処理JSエラー・決済呼び出しが0件であることも検査する。
